# MINDO Chat Backend

> **Using the live app from a phone?** MINDO is not optimised for mobile screens yet, and visuals may look broken. Please use your browser's **Desktop site** option.

Chatbot backend for [MINDO](https://github.com/reshavCodex/mindo-frontend), an AI-assisted counselling and wellness platform for students and young adults.

**Public service:** https://mindo-chat-backend.onrender.com (Render free tier, may sleep when idle)

> To try the full app, open this URL once to wake the service (along with the [conversation](https://mindo-conversation.onrender.com) and [RAG](https://mindo-rag.onrender.com) services), then visit https://mindo-frontend.vercel.app. This is only because of free-tier hosting.

---

## Purpose

A small FastAPI service that powers MINDO's text chatbot. It receives a message (and optionally earlier messages), builds a prompt, and returns a reply generated by Google Gemini.

## Role in MINDO

```text
Frontend (/chat page) → Chat Backend → Gemini
```

This is separate from the realtime counselling flow. The check-in service ([mindo-conversation](https://github.com/reshavCodex/mindo-conversation)) handles live audio, emotion signals, sessions, reports and storage. The chat service only handles text and has none of those dependencies: no WebSocket, Firebase, Supabase or emotion model, and only six Python packages. Keeping it separate means the lightweight chatbot can run and be deployed on its own and does not depend on the heavier session service.

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| GET | `/` | Service status |
| GET | `/health` | Liveness check |
| POST | `/api/chat` | Get a chatbot reply |

### `POST /api/chat`

Request:

```json
{
  "message": "I'm stressed about exams.",
  "conversation": [
    { "role": "user", "content": "Hi" },
    { "role": "assistant", "content": "Hi. How are you feeling today?" }
  ]
}
```

`message` is required (non-empty). `conversation` is optional and holds earlier messages, oldest first.

Response:

```json
{
  "answer": "Exam pressure can make it harder to focus...",
  "sources": []
}
```

`sources` is part of the response schema (`source`, `page_start`, `page_end`) but is currently always an empty list.

## Request/Response Flow

1. The frontend sends `message` plus earlier messages in `conversation`.
2. `ChatService` joins the earlier messages into a text history.
3. It builds one prompt: system instruction, conversation history, latest message.
4. The prompt is sent to Gemini through the `google-genai` SDK.
5. The reply text is returned as `answer` (with a short fallback prompt if Gemini returns nothing).

The service is stateless: it stores nothing, so conversation history must be sent by the client with each request.

## Gemini Integration

`app/chat_service.py` uses `google-genai` with the model from `GEMINI_MODEL` (default `gemini-3.5-flash-lite`). The built-in system instruction asks for a calm, focused wellbeing conversation: acknowledge the user's latest message, give a short useful response where appropriate, ask one relevant follow-up question, avoid diagnosis, and prioritise urgent real-world support if the user expresses intent to harm themselves or others.

## Environment Variables

Names only. Never commit values. Locally the app reads `.env`.

| Variable | Purpose |
|---|---|
| `GEMINI_API_KEY` | Gemini access (required; startup fails without it) |
| `GEMINI_MODEL` | Gemini model name (optional; defaults to `gemini-3.5-flash-lite`) |
| `ALLOWED_ORIGINS` | Comma-separated CORS origins (defaults to `http://localhost:5173,http://127.0.0.1:5173`) |
| `RAG_BASE_URL` | Base URL used by `app/rag_client.py` (defaults to `http://127.0.0.1:8001`); see note below |

## Local Setup

```bash
git clone https://github.com/reshavCodex/mindo-chat-backend.git
cd mindo-chat-backend
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Create a `.env` file with at least `GEMINI_API_KEY`.

## Running Locally

```bash
uvicorn app.main:app --reload --port 8002
```

Then set `VITE_CHAT_API_URL=http://127.0.0.1:8002` in the frontend `.env`. Any free port works.

## Deployment

Deployed as a Render web service at https://mindo-chat-backend.onrender.com. Set `GEMINI_API_KEY`, optionally `GEMINI_MODEL`, and set `ALLOWED_ORIGINS` to the deployed frontend origin (`https://mindo-frontend.vercel.app`) in the Render dashboard. On the free tier the service sleeps when idle.

## Relationships

- **Frontend:** the `/chat` page calls `POST {VITE_CHAT_API_URL}/api/chat`.
- **Conversation Backend:** no connection. This service has no access to sessions, reports or Firebase.
- **RAG Backend:** the repo contains `app/rag_client.py`, which can call the RAG service's `POST /api/v1/chat/retrieve` endpoint, but `ChatService` does not currently use it, so replies are not retrieval-augmented and `sources` stays empty.
- **Supabase / Firebase:** not used.

## Security

- `GEMINI_API_KEY` is read from the environment; `.env` is git-ignored. Never commit it.
- The endpoint has no authentication, so anyone who can reach the URL can send requests and use Gemini quota. CORS (`ALLOWED_ORIGINS`) limits browsers, not other clients.
- User messages are printed to the server logs; review logging before handling real user data.
